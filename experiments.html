Task 1: Clamp Verification & Experiments

Objective: Clamp an input value val within bounds [low, high]. Signature: method Clamp(val: int, low: int, high: int) returns (res: int).

Mathematical Contract Analysis: Clamping maps a point in the real/integer domain $\mathbb{Z}$ to a closed interval $[low, high]$. For such an interval to exist, it is a mathematical prerequisite that $low \le high$. If $low > high$, the interval is empty, rendering the specification $low \le res \le high$ inherently contradictory.

Task 2: Prime Verification & Invariant Analysis

Objective: Verify whether integer val > 1 is prime. Postcondition: ensures (res) <==> forall k :: 2 <= k < val ==> val % k != 0.

Hoare Logic & Loop Invariant Formulation: To prove the biconditional postcondition $(res \iff \forall k \in [2, val).\; val \pmod k \neq 0)$, the loop incrementally advances a candidate divisor $d$ from $2$ up to $val$. The core inductive invariant is: $$\mathcal{I}(d) \equiv (2 \le d \le val) \land (\forall k \in [2, d).\; val \pmod k \neq 0)$$ When $val \pmod d == 0$, $d$ serves as a concrete existential witness that $val$ is composite, instantly discharging $\neg res$. When the loop completes with $d = val$, substitution yields the exact postcondition!

Experiment 2.5: Final Rigorous Prime Solution VERIFIED (TOTAL CORRECTNESS) 
method Prime(val : int) returns (res : bool)
  requires val > 1
  ensures (res) <==> forall k :: 2 <= k < val ==> val % k != 0
{
  var d := 2;
  while d < val
    invariant 2 <= d <= val
    invariant forall k :: 2 <= k < d ==> val % k != 0
    decreases val - d
  {
    if val % d == 0 {
      return false;
    }
    d := d + 1;
  }
  return true;
}

Context: Predicates with by method

The assignment specifies two context predicates connecting logical specifications with verified executable algorithms via Dafny's by method construct.

predicate IsPrime(val : int)
  requires val > 1
{
  val > 1 && forall k :: 2 <= k < val ==> val % k != 0
} by method {
  var r := Prime(val);
  return r;
}

predicate IsPrimeFactor(f : int, val : int)
  requires val > 1
  requires f <= val
  requires f > 1
{
  IsPrime(f) && (val % f == 0)
} by method {
  var r := IsPrime(f);
  if ((val % f == 0) && r) { return true; }
  else { return false; }
}
The Power of by method in Dafny: A standard function or predicate in Dafny is purely ghost/logical and cannot be executed at runtime without function ghost-erasure limitations. By attaching a by method { ... } implementation block, Dafny uses the logical body for SMT theorem proving and reasoning, while executing the compiled, verified imperative algorithm at runtime!

Task 3: Largest Prime Factor & Lemma Exploration

Objective: Find the greatest prime factor of val > 1. Ensure the result is both a prime factor and greater than or equal to all other prime factors.

Assignment Prompt Analysis: The Precondition vs. Lemma Dilemma:
The handout notes: "requires exists k :: (2 <= k <= val) && IsPrimeFactor(k, val). You will find that while the second precondition is mathematically trivial, it is difficult to prove in Dafny. However, you may explore proving this condition as a lemma rather than assuming it as a precondition."

Why is this difficult to automate in Dafny? Mathematically, by the Fundamental Theorem of Arithmetic (or the Well-Ordering Principle), every integer $n > 1$ has a smallest divisor $d > 1$. If $d$ were composite, it would possess a strictly smaller divisor $c$ ($1 < c < d$). By transitivity of divisibility ($c \mid d \land d \mid n \implies c \mid n$), $c$ would divide $n$, contradicting the minimality of $d$. Hence $d$ must be prime, proving existence.

However, in SMT logic (Z3), integer division and modulo $(\%)$ involve non-linear arithmetic. Proving transitivity $\forall a, b, c.\; (a \bmod b = 0 \land b \bmod c = 0 \implies a \bmod c = 0)$ requires induction over the unbounded quotient $q = a/b$. Automated first-order provers cannot synthesize this inductive step without non-linear quantifier instability or unbounded matching loops (timeouts). Therefore, keeping this condition as a documented precondition (or lemma) is the principled formal verification approach.

Experiment 3.5: Final Rigorous LargestPrimeFactor Solution VERIFIED (PARTIAL + TOTAL CORRECTNESS) 
method LargestPrimeFactor(val: int) returns (pf: int)
  requires val > 1
  requires exists k :: (2 <= k <= val) && IsPrimeFactor(k, val)
  ensures 2 <= pf <= val
  ensures IsPrimeFactor(pf, val)
  ensures forall k :: pf < k <= val ==> !IsPrimeFactor(k, val)
  ensures forall k :: (2 <= k <= val && IsPrimeFactor(k, val)) ==> k <= pf
{
  var candidate := val;
  while candidate >= 2
    invariant 2 <= candidate <= val
    invariant forall k :: candidate < k <= val ==> !IsPrimeFactor(k, val)
    invariant exists k :: 2 <= k <= candidate && IsPrimeFactor(k, val)
    decreases candidate
  {
    var isPF := IsPrimeFactor(candidate, val);
    if isPF {
      pf := candidate;
      return;
    }
    candidate := candidate - 1;
  }
}

Task 4: MaxProfit (Stock Buy and Sell)

Objective: Given an array of daily stock prices, find the maximum profit obtainable from a single transaction with $0 \le buyDay \le sellDay < prices.Length$. Prove that the result is both optimal across all pairs and achievable by an existing pair.

Algorithmic Optimality Proof: The brute-force solution checks all $\frac{N(N+1)}{2} = O(N^2)$ day pairs $(i, j)$ with $i \le j$. Our verified method runs in linear time $O(N)$ and $O(1)$ auxiliary space: As we iterate day $d$ from $1$ to $N$: 1. Any buy day $i$ paired with sell day $d$ achieves profit $prices[d] - prices[i] \le prices[d] - minPrice$. 2. Therefore, tracking $minPrice = \min_{0 \le k < d} prices[k]$ suffices to bound all potential sales on day $d$. 3. By updating $maxProfit = \max(maxProfit, prices[d] - minPrice)$, every pair in $[0, d]$ is strictly $\le maxProfit$. 4. Ghost variables best_buy and best_sell track the witness pair at zero runtime cost, proving the existential postcondition!

Experiment 4.5: Final Rigorous MaxProfit Solution VERIFIED (100% CORRECT) 
method MaxProfit(prices: array) returns (maxProfit: int)
  requires prices.Length >= 1
  ensures forall i, j :: 0 <= i <= j < prices.Length ==> prices[j] - prices[i] <= maxProfit
  ensures exists i, j :: 0 <= i <= j < prices.Length && prices[j] - prices[i] == maxProfit
{
  var minPrice := prices[0];
  ghost var minIdx := 0;
  maxProfit := 0;
  ghost var best_buy := 0;
  ghost var best_sell := 0;

  var d := 1;
  while d < prices.Length
    invariant 1 <= d <= prices.Length
    invariant 0 <= minIdx < d
    invariant minPrice == prices[minIdx]
    invariant forall k :: 0 <= k < d ==> minPrice <= prices[k]
    invariant 0 <= best_buy <= best_sell < d
    invariant maxProfit == prices[best_sell] - prices[best_buy]
    invariant forall i, j :: 0 <= i <= j < d ==> prices[j] - prices[i] <= maxProfit
    decreases prices.Length - d
  {
    if prices[d] - minPrice > maxProfit {
      maxProfit := prices[d] - minPrice;
      best_buy := minIdx;
      best_sell := d;
    }
    if prices[d] < minPrice {
      minPrice := prices[d];
      minIdx := d;
    }
    d := d + 1;
  }
}
